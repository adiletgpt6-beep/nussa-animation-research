# Технологический план автоматизированного производства (2D и стилизованное 3D)

Дата: 2026-11-25. Статус: **план для утверждения**; производство не начато.

Дополняет `production/PRODUCTION_TECH_PLAN.md`, где описан классический студийный вариант на 6–8 человек. Здесь — **максимальная автоматизация при минимальной команде**.

## Метки

| Метка | Значение |
|---|---|
| **[П]** | Проверено: факт об инструменте с источником или проверено нами |
| **[Т]** | Техническая оценка: работает в принципе, качество подтвердит тестовая сцена |
| **[Н]** | Не проверено: лицензию или возможность проверить до использования |

## 0. Честная граница автоматизации

**Что автоматизация делает хорошо [Т]:**
- сборка сцен;
- камеры и свет по шаблонам;
- **lip sync**;
- **моргания, саккады, дыхание**;
- вторичное движение ткани;
- рендер, сведение звука, контроль качества;
- документация и проверки сценария.

**Что автоматизация не делает на нужном уровне [Т]:**
- **актёрская игра тела и лица**: смена эмоций, комедийный тайминг, «живые паузы»;
- сложное взаимодействие рук с предметами;
- художественный дизайн героев.

Здесь нужен человек:
- аниматор;
- исполнитель для захвата движения — может быть сам заказчик или член семьи;
- художник.

**Чего мы НЕ используем для финальных кадров:**
- **AI-генераторы видео** (Sora, Veo, Kling, Runway и подобные):
  - не держат стабильно одного и того же героя от кадра к кадру;
  - не дают управляемого lip sync русской речи;
  - не гарантируют соблюдения запретов на изображения;
  - стоят денег за каждую попытку.

  Допустимо только для референсов настроения.
- **AI-генерацию картинок как финальный дизайн героев:**
  - правовой статус таких изображений не определён;
  - есть риск сходства с чужими персонажами.

  Допустимо для поиска идей; финал рисует художник.
- **«Говорящие головы» поверх статичной картинки** — прямо запрещено ТЗ.

**Роль Claude Code [Т].** Пишет и поддерживает Python- и `bpy`-скрипты конвейера, собирает сцены из сценария, запускает рендер и QC, проверяет кадры по отрендеренным изображениям, ведёт документацию.

Чего он не может:
- работать в интерактивном окне Blender в реальном времени;
- заменить вкус художника;
- без исполнителя или аниматора сделать актёрскую игру уровня Nussa.

## 1. Архитектура

```
 Сценарий (Markdown + YAML: сцены, реплики, эмоции, действия, камеры)
   │  CI: хронометраж 240–360 с, хук ≤ 5 с, [REL]-маркеры подписаны устазом, чек-лист запретов
   ▼
 Голоса ─► WAV по репликам ─► выравнивание: фонемы и время (MFA ru / таймстемпы ElevenLabs)
   ▼
 Аниматик: Blender собирает сцену из YAML (локация, камеры, расстановка, звук) ─► EEVEE-превью
   ▼
 Анимация по слоям (каждый слой — отдельный Action / NLA-полоса):
   L1 тело:   захват движения исполнителя ИЛИ библиотечные экшены ИЛИ ключи аниматора
   L2 руки:   захват и передача предметов (constraints, переключение скриптом)
   L3 лицо:   эмоции из YAML-тегов ─► позы из библиотеки ─► (опц.) захват мимики с камеры
   L4 рот:    виземы из фонем — автоматически
   L5 глаза:  моргания, саккады, взгляд на собеседника — процедурно
   L6 вторичное: ткань и spring bones — симуляция с запеканием
   ▼
 Ручная доводка аниматором (только L1–L3, ключевые моменты)
   ▼
 Свет по шаблону локации и времени суток ─► рендер EEVEE (S2/S3) или Grease Pencil (S1)
   ▼
 Звук: реплики + неречевые звуки героя + фоли + атмосферы (без музыки) ─► FFmpeg-сведение
   ▼
 Автоматический QC ─► отчёт ─► просмотр заказчиком и устазом ─► мастер
```

## 4. Вариант стилизованное 3D (S3, и S2 из того же файла)

| Компонент | Как | Автоматизация |
|---|---|---|

| Риг | Rigify + лицевые shape keys (12 эмоций, 10–12 визем, веки, брови) + кости глаз | частично: скрипт переносит риг между героями одного тела |

| Глаза | Процедурно (как в 2D) | **полная** |
| Руки и предметы | Constraint «Child Of» с переключением по меткам YAML (`take: bag @1.2s`) | полуавтоматически |
| Ткань | Cloth sim с запеканием или spring bones | **полная** после настройки |
| Свет | Шаблоны «день / вечер / ночь» на каждую локацию | **полная** |
| Рендер | EEVEE (быстро) для S3; toon-материалы + Line Art для S2 | **полная** |

## 5. Что даёт «живые движения всего тела» без большой студии

Три пути, выбор — по тестовой сцене.

1. **Захват движения исполнителя [Т]** — самый дешёвый.
   - Заказчик или нанятый актёр играет сцену перед 1–2 камерами (телефон).
   - Открытая оценка позы → анимация скелета → ретаргетинг на мультяшный риг → чистка: стопы, руки, преувеличение поз.
   - Мимика — отдельно, веб-камерой через MediaPipe.
   - Ограничения: дрожание, скольжение стоп, «реалистичная» а не мультяшная подача. Чистка ≈ 0,5–2 ч на 10 с анимации [Т].
2. **Библиотека экшенов.** Ходьба, бег, сесть, встать, взять, жесты для каждого базового тела. Хорошо для массовых и фоновых действий, плохо для главной игры.
3. **Аниматор-фрилансер** на ключевые сцены и доводку: 20–40 % хронометража серии. Остальное — пути 1–2 и процедурные слои.

## 6. Автоматический QC (каждая серия)

| Проверка | Как | Порог |
|---|---|---|
| Длительность | ffprobe | 240–360 с |
| Формат | ffprobe | 1920×1080, 30 fps CFR |
| Громкость | ffmpeg ebur128 | −14…−16 LUFS, TP ≤ −1 dBTP |
| **Нет фоновой музыки** | `research/pipeline/audio_analysis.py` (классификатор AST) | доля окон с музыкой ≥ 0,5 — около 0 |
| «Замёрзшие» кадры | разность кадров | нет участков > 2 с без движения, если это не задумано (метка в YAML) |
| **Lip sync** | данные Blender: значение визем MBP в моменты «м/б/п» по MFA | рот закрыт ≥ 1 кадр на каждом «м/б/п»; рассинхрон ≤ 2 кадров |
| **Моргания** | ключи век | интервал 2–6 с, нет одновременных морганий у всех героев |
| Слушающий герой | ключи головы и глаз | реакция не реже 1 раза в 3 с |
| Хук | сценарий + аниматик | первое действие или реплика ≤ 5 с |
| Религиозные маркеры | YAML | все `[REL]` имеют подпись устаза |
| Запреты изображений | ручной чек-лист устаза по аниматику | — |

## 7. Повторное использование

| Что | Где хранится | Как переиспользуется |
|---|---|---|
| Базовые тела и риги | Blender Asset Library (linked) | новые персонажи за 1–3 дня |
| Экшены (ходьба, эмоции, жесты) | Asset Library, по базовым телам | NLA-полосы в любой серии |
| Лицевые позы и виземы | shape keys + pose library | одинаковые имена у всех героев → скрипты работают для всех |
| Локации | файл-локация с камерами и светом «день / вечер / ночь» | связываются, а не копируются |
| Реквизит | с точками захвата | один `take:` в YAML |
| Голоса | актёр по договору или `voice_id` + параметры; библиотека неречевых звуков героя | постоянство голоса |
| Звуки | библиотека SFX с тегами | автоматическая подстановка по YAML (`sfx: door_open`) |
| Скрипты и QC | GitHub | каждая серия |
