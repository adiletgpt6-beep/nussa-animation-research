# Практический технический план производства (по итогам VID-001)

Дата: 2026-11-25. Статус: **план для утверждения**; производство не начато.
Основание: технический разбор VID-001 (`research/vid001/VID001_ANALYSIS.md`) и исследование 15 серий (`research/FINAL_REPORT.md`).

## Как читать

| Метка | Значение |
|---|---|
| **[П]** подтверждено | Измерено или увидено в VID-001 |
| **[Т]** техническое предположение | Вывод инженера по косвенным признакам |

## 0. Главный вывод для выбора технологии

- **[П]** Nussa — **3D CGI**, а не 2D:
  - объёмные персонажи с материалами (кожа, ткань хиджаба, дерево, пластик);
  - мягкий глобальный свет, малая глубина резкости, объёмный туман;
  - симуляция или вторичная анимация ткани;
  - анимация «на единицах» при 25 fps.
- **[П]** Команда 3-го сезона по финальным титрам невелика:
  - супервайзер анимации и **2 аниматора**;
  - **1 риггер**;
  - супервайзер и 1 художник создания ассетов;
  - 4–5 человек на свет и композитинг (look development, lighting, compositing);
  - монтажёр, звукорежиссёр, руководитель аудиопоста;
  - сценарист, раскадровщик, директор озвучания, 7 актёров основных ролей.

  Такое качество достижимо **небольшой командой** при сильной библиотеке ассетов и стандартизированных сценах: дом, кухня, детская, двор.
- **[Т]** Сопоставимое с Nussa качество быстрее и дешевле получить **в 3D (Blender)**, чем в рисованном 2D: 2D потребует больше ручного труда на кадр.

### Решение по пилоту

Решение принимает заказчик. По плану проекта первая серия — **2D**. Рекомендуется:
- **Вариант А (по плану):** 2D-пилот в Blender Grease Pencil с 3D-окружениями.
- **Вариант Б (по итогам VID-001):** пилот сразу в **стилизованном 3D** в Blender. Персонажи, риги, окружения и экшены пилота сразу становятся сериальной библиотекой — без двойной работы «2D → 3D».

Сравнение — в разделе 6.

## 1. Архитектура производства

```
Сценарий (Markdown + YAML) ──► проверка устазом/психологом ──► Gate
       │
       ▼
Озвучка: ElevenLabs (черновик и кастинг) или актёры (финал)
       │  ──► WAV по репликам + таймстемпы символов (JSON)
       ▼
Аниматик (Blender: раскадровка в 3D-пространстве + звук) ──► Gate
       │
       ▼
Сборка сцен (Python/bpy): локации из библиотеки, персонажи (linked rigs), камеры,
  экшены (walk/sit/gesture), автоматический lip sync, моргания, взгляды
       │
       ▼
Ручная анимация: аниматоры доводят ключевые позы, эмоции, тайминг гэгов
       │
       ▼
Симуляции (ткань хиджаба и одежды, волосы) ─► свет (шаблоны по локациям) ─► рендер (Flamenco / облачный GPU)
       │
       ▼
Композитинг (Blender compositor) ─► звук: фоли, атмосферы, без музыки ─► FFmpeg-мастер ─► автоматический QC ─► Gate
```

## 2. Технологии

| Задача | Технология | Почему | Метка |
|---|---|---|---|
| Моделирование, риг, анимация, свет, рендер | **Blender** | Бесплатно; полный Python API; Cycles для качества, EEVEE для скорости; Grease Pencil для 2D | [Т] |
| Риг тела | Rigify + доработка | Стандартные имена костей, IK/FK, переиспользование | [Т] |
| Лицевой риг | shape keys (виземы + эмоции) + кости век, глаз, бровей | Lip sync и мимика из данных | [Т] |
| Lip sync | Таймстемпы ElevenLabs → русский маппер «буква → визема» → ключи shape keys; запасной вариант — Rhubarb | Точный тайминг без ручной расстановки | [Т] |
| Моргания и микродвижения | Процедурный генератор: моргание каждые 2–6 с, на поворотах головы, длительность 3–5 кадров; дыхание; саккады глаз | В VID-001 моргания стоят на поворотах головы и длятся около 2 кадров закрытых век | [П] / [Т] |
| Ткань (хиджаб, подол, рукава) | Cloth simulation с запеканием или кости с пружинами (spring bones) | В VID-001 подол и одежда двигаются с запаздыванием | [П] / [Т] |
| Голоса | ElevenLabs (v3/v4 — эмоции, multilingual_v2 — стабильность) или актёры | Ключ проверен через API; баланс неизвестен | [П] |
| Звук | Библиотека фоли и атмосфер + запись фоли + неречевые звуки голоса (вздохи, ахи, всхлипы); **без фоновой музыки** (требование) | В VID-001 у E01–E06 под речью музыка, а E07–E13 идут без музыки и держатся на голосе и шумах (классификатор; на слух не проверено) | [П] / [Т] |
| Рендер-менеджер | Flamenco (открытый, от Blender) или облачный GPU по запросу | Распределённый рендер без лицензий | [Т] |
| Мастер и QC | FFmpeg + Python (`research/pipeline/` уже содержит метрики планов и звука) | Проверка длительности, громкости, fps, разрешения, «замёрзших» кадров | [П] |
| Хранение ассетов | Git LFS или облачное хранилище + Blender Asset Library | Версии персонажей и локаций | [Т] |
| CI | GitHub Actions | Проверка сценария, QC готового файла, аниматики; без рендера финала | [Т] |

## 3. Автоматизация (что делает код, а что — человек)

| Тело | Библиотечные экшены: ходьба, бег, сесть, встать, жесты | **Актёрская игра**, комедийный тайминг, взаимодействие с предметами |

## 5. Контроль качества (приёмка серии)

- Технически:
  - 1920×1080, 30 fps (CFR), 240–360 с;
  - −14…−16 LUFS, true peak ≤ −1 dBTP;
  - нет «замёрзших» кадров и тишины длиннее 2 с без смысла;
  - нет фоновой музыки.
- Анимация:
  - моргания 2–6 с;
  - lip sync: рот закрывается на «м/б/п», рассинхрон ≤ 2 кадров;
  - стопы не скользят, предметы не «плавают»;
  - слушающий персонаж реагирует.
- Содержание:
  - хук ≤ 5 с;
  - отметка устаза;
  - нет изображения пророков, ангелов, шайтана;
  - нет рекламы.

## 6. 2D или 3D для пилота — сравнение

| Критерий | 2D (Grease Pencil + 3D-окружения) | Стилизованный 3D (Blender) |
|---|---|---|
| Сходство с качеством Nussa | Другое по природе: рисованная выразительность | **Прямо сопоставимо [Т]** |
| Трудоёмкость на минуту | Выше: позы и повороты рисуются | Ниже после создания ригов |
| Повторное использование | Риги частей; повороты требуют рисунков | Полное: риги, экшены, свет |
| Переход дальше | Нужен отдельный 3D-этап | Не нужен |
| Риск «дешёвого вида» | Марионеточность cut-out без сильного аниматора | «Пластиковость» без хорошего look development |
| Рекомендация | Если заказчику важен рисованный стиль | **Если цель — качество уровня Nussa при минимальной двойной работе** |

**Предлагаемое решение (требует утверждения):** провести технический прототип (Gate 5 в `DEVELOPMENT_PLAN.md`) **в обоих вариантах на одной сцене 15–20 с** и выбрать по результату.
