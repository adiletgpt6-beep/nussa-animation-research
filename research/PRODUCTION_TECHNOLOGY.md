## 1. Требование к результату

Нужна **настоящая анимация**, а не «картинки с зумом». Отсюда технические требования:

| Требование | Что это значит технически |
|---|---|
| Персонажи ходят и бегают | Риг ног с IK, библиотека циклов ходьбы/бега (12–16 кадров на шаг при 30 fps), контакт стоп с полом без проскальзывания |
| Говорят | Виземы (6–9 форм рта) по таймингу речи, плюс движения челюсти, головы и бровей на ударных слогах |
| Двигают глазами | Отдельные слои зрачков/век, моргание каждые 2–6 с (нерегулярно), взгляд опережает поворот головы на 2–4 кадра |
| Двигают руками и ногами | Скелетный риг с FK/IK, сменные кисти (8–12 поз рук), «Smart bones»/корректирующие формы на локтях и коленях |
| Взаимодействуют с предметами и друг с другом | Привязка предметов к кости руки (child-of с переключением), общая сцена с глубиной (Z-порядок/3D-пространство) |
| Живут в кадре | Вторичное движение (ткань, волосы, хиджаб/шапочка), дыхание в паузах, «перекрытие» действий |
| 1920×1080, 16:9, 30 fps, 4–6 мин | Рендер-пресет проекта, FFmpeg-контроль длительности и параметров |

## 2. Сравнение инструментов

Оценки: 1 — плохо, 5 — отлично. Оценки экспертные, это не результат бенчмарка.

| Инструмент | Качество 2D-анимации | Стоимость | Автоматизация (Python/CLI) | Повторное использование персонажей | Путь в 3D | Вывод |
|---|---|---|---|---|---|---|
| **Blender + Grease Pencil (v3, Blender 4.3+)** | 4–5: штриховая и заливочная 2D-графика в 3D-пространстве, риг арматурой, модификаторы, слои | Бесплатно (GPL) | **5**: полный `bpy` API, headless-рендер `blender -b … -a` | 5: персонаж — asset в библиотеке, экшены (Actions) переиспользуются | **5**: тот же софт, те же камеры, окружения, скрипты и звук | **Основной выбор** |
| OpenToonz | 5 для покадровой (frame-by-frame) рисованной анимации, хорош «Plastic tool» | Бесплатно | 2: ограниченный скриптинг, конвейер сложно автоматизировать | 3: возможен cut-out, но риг слабее | 1: нет | Для рисованных FX и ключевых эмоциональных сцен, как вспомогательный |
| Synfig Studio | 3: векторный cut-out с костями; при упрощённой графике выглядит «флэшево» | Бесплатно | 4: формат `.sif` — XML, легко генерировать; CLI-рендер | 3 | 1 | **Не рекомендуется как основной**: высокий риск «примитивного SVG-вида», который заказчик явно не хочет |
| Moho Pro (справочно) ⚠ | 5 для TV cut-out (Smart Bones, переключаемые слои) | Платно, разовая лицензия | 3: Lua-скрипты | 5 | 1 | Сильная платная альтернатива, если команда аниматоров уже с ним работает |
| Toon Boom Harmony (справочно) ⚠ | 5, отраслевой стандарт TV 2D | Подписка, дорого | 3: JS/Python в старших версиях | 5 | 2 | Избыточен для старта с автоматизированным конвейером |
| Cartoon Animator / Character Animator (справочно) ⚠ | 3–4, быстро, но шаблонно | Платно | 2–3 | 4 | 1 | Риск узнаваемого «шаблонного» вида |

### Почему Blender + Grease Pencil

1. **Один инструмент на весь путь 2D → 3D.** Окружения, камеры, свет, звук, раскадровки и скрипты сборки, сделанные для 2D-пилота, переходят в 3D-сериал без переделки.
   - Можно строить «2.5D»: 2D-персонажи Grease Pencil внутри 3D-окружений. Камера тогда реально движется в глубине, что сильно отличается от зума по картинке.
2. **Автоматизация.** Python-скрипт собирает сцену из сценария (YAML/JSON):
   - расставляет персонажей;
   - накладывает экшены из библиотеки («идёт», «садится», «машет», «удивляется»);
   - ставит ключи визем по таймингу речи;
   - рендерит без интерфейса.
3. **Бесплатность** и отсутствие привязки к вендору.
4. **Повторное использование.** Персонаж хранится как asset (риг, виземы, сменные кисти, наборы эмоций) и подключается в каждую серию через linked library. Правки персонажа распространяются на все серии.

### Где нужна ручная работа аниматора (автоматизация не заменит)

- ключевые позы актёрской игры в эмоциональных сценах;
- тайминг комедийных моментов;
- проверка силуэтов и «читаемости» действия;
- финальная полировка: overlap, settle, антиципация.

Реалистичная схема: **скрипт строит черновую сцену (layout + lip sync + базовые действия) → аниматор доводит ключевые моменты → скрипт рендерит и собирает.**

## 3. Техника анимации: cut-out, покадровая или гибрид

| Подход | Плюсы | Минусы | Применение |
|---|---|---|---|
| Cut-out (риг из частей) | Быстро, повторяемо, легко автоматизировать, стабильный «он-модель» | Без доработки — «марионеточность» | Тела, ходьба, жесты, диалоговые сцены (≈80% хронометража) |
| Покадровая (frame-by-frame) | Максимальная выразительность | Дорого и медленно, не автоматизируется | Ключевые эмоции, сквош-стрейч, эффекты (вода, пыль, слёзы, искры) |
| **Гибрид (рекомендуется)** | Скорость cut-out + выразительность рисованных вставок | Нужна дисциплина ассетов | Риг + сменные рисованные части: рты, кисти, глаза, «смазы» в быстрых движениях |

Обязательные элементы рига каждого персонажа:
- кости тела с IK на ногах и руках;
- поворот головы 3/4 ↔ профиль сменой рисунков (3–5 ракурсов головы);
- 9 визем;
- 6–8 базовых эмоций бровей и век;
- 10 поз кистей;
- «дыхательная» кость;
- кости вторичного движения для волос и одежды.

## 4. Автоматическая синхронизация губ (русская речь)

| Вариант | Как работает | Русский язык | Оценка |
|---|---|---|---|
| **Тайминги ElevenLabs + свой русский маппер «буква → визема»** | API синтеза с таймстемпами возвращает время каждого символа. Русская орфография близка к фонетике, поэтому таблица соответствия букв и визем (с учётом ударения и редукции гласных) даёт точный тайминг | ✅ нативно | **Основной вариант**: тайминг точнее распознавания по звуку, работает с любым языком |
| Rhubarb Lip Sync (open source, CLI) | Анализ аудио, выдаёт формы рта A–H, X по времени | ⚠ английский распознаватель; для других языков есть режим `phonetic` | Резервный вариант и проверка; годится для записей живых актёров |
| Papagayo-NG | Ручная расстановка фонем | ручная | Для правки отдельных реплик |
| Анализ громкости (amplitude) | Открытие рта по уровню сигнала | любой | Только как добавка к челюсти; сам по себе выглядит дёшево |

Помимо губ, анимация речи должна включать:
- кивки и движения бровей на ударных словах (выделяются из тайминга и пиков громкости);
- моргание на границах фраз;
- реакцию слушающего персонажа, которому нельзя «замирать».

3. **Тайминги**: запрос с таймстемпами символов, из которых строятся виземы (п. 4).

5. **Оценка объёма**:
   - 5-минутная серия ≈ 350–550 слов диалога ≈ 2,5–4 тыс. символов;
   - с дублями ×3–5 ≈ 10–20 тыс. символов на серию;
   - ⚠ стоимость нужно сверить с текущим тарифом до запуска.

## 6. FFmpeg, Python, GitHub Actions

| Задача | Инструмент | Детали |
|---|---|---|
| Сборка звука (речь + шумы + музыка/нашид) | FFmpeg `amix`/`sidechaincompress` | Приглушение фона под речью на 8–12 дБ |
| Нормализация громкости | FFmpeg `loudnorm` (2 прохода) | Цель −14…−16 LUFS integrated, true peak ≤ −1 dBTP ⚠ (YouTube нормализует воспроизведение около −14 LUFS) |
| Финальный мастер | FFmpeg | H.264 High, 1920×1080, 30 fps CFR, yuv420p, BT.709, CRF 16–18; AAC 48 кГц 256–320 кбит/с |
| Сборка сцены из сценария | Python + `bpy` | Сценарий YAML → сцены, экшены, виземы, камера |
| Автоматический контроль качества (QC) | Python (ffprobe, OpenCV) | Длительность строго 240–360 с, разрешение и fps, громкость, чёрные или «замёрзшие» кадры, тишина > 2 с, доля статичных кадров |
| CI | GitHub Actions | Проверка сценария (длина, лексика, обязательный блок «проверено устазом»), QC готового файла, рендер аниматика в низком разрешении |

⚠ Финальный рендер 1080p лучше выполнять на рабочей станции с GPU или на арендованном GPU **после согласования бюджета**. Бесплатные раннеры GitHub без GPU годятся для проверок и аниматиков, но не для продакшн-рендера.

## 7. Конвейер (рекомендуемый)

```
Сценарий (Markdown + YAML-разметка реплик и действий)
   │  ▸ проверка устазом (обязательный шаг, отметка в файле)
   ▼
Озвучка (ElevenLabs или актёр) ──► тайминги символов ──► русский маппер визем
   │
   ▼
Аниматик: раскадровка + звук (Blender, грубые позы) ──► утверждение
   │
   ▼
Сборка сцен скриптом (bpy): персонажи-ассеты + библиотека экшенов + виземы + камеры
   │
   ▼
Ручная анимация ключевых моментов (аниматор) ──► полировка
   │
   ▼
Рендер (EEVEE/Workbench для GP) ──► FFmpeg: звук, громкость, мастер ──► автоматический QC
```

## 8. Подготовка к переходу на 3D уже в 2D-пилоте

1. Дизайн персонажей с **простыми объёмными формами** и турнарандами (вид спереди, 3/4, профиль, сзади): по ним потом строится 3D-модель.
2. **Единая система имён** костей и экшенов («walk_normal», «sit_down», «wave_R»), чтобы 3D-риг (Rigify) получил те же имена и сценарные скрипты работали без изменений.
3. **Виземы как данные**, а не как рисунок. JSON «время → визема» подходит и для 2D-слоёв, и для 3D shape keys.
4. **Окружения сразу строить в 3D** (простая геометрия + 2D-текстуры): в 3D-версии они уточняются, а не создаются заново.
5. **Свет и цвет**: палитра и ключевые схемы освещения фиксируются в `production/WORLD_DESIGN.md`, для 3D применяется тот же цветовой сценарий (color script).
